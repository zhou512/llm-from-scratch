# 笔记 05 · PR 流程本地演练（不用 GitHub 也能练）

> 配套脚本：`git-practice/local-remote/demo-pr.ps1`
> 跑法：`powershell.exe -NoProfile -File git-practice\local-remote\demo-pr.ps1`
> 它会重建 `git-practice/local-remote/workdir/`，可以反复跑。

---

## 为什么要在本地演练

真正的 PR 要 GitHub 账号 + 网络 + 网页点按钮。
但 git 的「**开分支 → 提交 → 推送 → 合并 → 清理**」这套动作，
用一个**裸仓库（bare repo）**当"远程"就能完整演练。

**网页上的按钮，对应的都是本地命令**：

| GitHub 网页操作 | 等价命令 |
|---|---|
| `Compare & pull request` | `git push -u origin <branch>` |
| `Files changed` | `git log --oneline origin/main..<branch>` |
| `Merge pull request` | `git switch main` + `git merge --no-ff <branch>` |
| `Delete branch` | `git branch -d <branch>` + `git push origin --delete <branch>` |
| 同步上游更新 | `git pull --ff-only origin main` |

---

## 演练的 9 个步骤

| 步骤 | 动作 | 学到什么 |
|---|---|---|
| 1 | `git init --bare --initial-branch=main remote.git` | 裸仓库 = 只有 `.git` 内容，没有工作区，专门当远程 |
| 2 | 造初始项目并 push | 模拟"别人已有的仓库" |
| 3 | `git clone` | 克隆下来的自动配好 `origin` |
| 4 | `git switch -c feat/add-gcd` | **★ 绝不在 main 上直接改** |
| 5 | `git push -u origin feat/add-gcd` | `-u` 记住上游，之后直接 `git push` |
| 6 | `git log --oneline origin/main..feat/add-gcd` | 看"PR 里会展示哪些提交" |
| 7 | `git merge --no-ff` | 保留合并痕迹，和 GitHub 点 Merge 一致 |
| 8 | 删本地 + 删远程分支 | 保持分支列表干净 |
| 9 | 模拟上游更新并同步 | `git pull --ff-only` |

## 两个实测踩到的坑

### 坑 1：`pwsh` 不一定在 PATH

```
pwsh : The term 'pwsh' is not recognized...
```

Windows 自带的是 **Windows PowerShell 5.1**（命令是 `powershell.exe`），
`pwsh` 是 PowerShell 7+ 才有的命令，要单独安装。

```powershell
# 用哪个都行，看装了什么
powershell.exe -File script.ps1     # 5.1（Windows 自带）
pwsh -File script.ps1               # 7+（需安装）
```

### 坑 2：★ PowerShell 5.1 读无 BOM 的 UTF-8 脚本会按 GBK 解析

报错长这样（而且指的行号是错的）：

```
At demo-pr.ps1:22 char:20
+ function Run($cmd) {
+                    ~
Missing closing '}' in statement block or type definition.
```

**原因**：PowerShell 5.1 默认按系统 ANSI 编码（中文 Windows 是 GBK）读 `.ps1` 文件。
脚本里有中文注释/字符串，就会被解码成乱码，引号配对被打乱 → 语法错误。

**修复**：给脚本加 **UTF-8 BOM**：

```powershell
$p = "path\to\script.ps1"
$content = [System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8)
[System.IO.File]::WriteAllText($p, $content, (New-Object System.Text.UTF8Encoding($true)))
#                                                                            ↑ $true = 带 BOM
```

或者更简单：在 VS Code 里把编码改成 **"UTF-8 with BOM"**（右下角编码按钮）。

> **这和 Python 的 `open()` 坑是同一类问题**：
> Windows 上的默认编码不是 UTF-8。凡是涉及"隐式默认编码"的地方，
> 都要显式指定，或者用带 BOM 的文件让工具自己识别。

**结论**：写 PowerShell 脚本、Python 脚本、配置文件，**中文都要注意编码**。
这是在国内 Windows 环境做开发的高频坑。

## 完整流程图

```
        main                    feat/add-gcd
          │                          │
          │ ① git switch -c         │
          ├─────────────────────────►│
          │                          │ ② 写代码
          │                          │ ③ git add + commit
          │                          │
          │                          │ ④ git push -u origin feat/add-gcd
          │                          ▼
          │                    [远程有分支了]
          │                          │
          │                          │ ⑤ 网页开 PR / 本地等价命令
          │                          │
          │ ⑥ git merge --no-ff ◄────┤
          │    (保留合并点)           │
          ▼                          │
      [main 前进]                     │ ⑦ 删分支
          │                          │
          │ ⑧ git pull --ff-only     │
          ▼                          ▼
      [和远程同步]
```
