# 笔记 02 · 初始化到底影响什么？（实测）

> 起因：用户观察到「把权值和偏置手工缩放后，训练结果没明显差异」，
> 提出假设：**100000 步已经足够让模型矫正不合适的初始化**。
>
> 验证脚本：`bench_init.py`、`probe_init_math.py`、`probe_seed_variance.py`

---

## 一、先说结论

> **用户的假设成立**：训练足够久以后，三种初始化的最终 loss 几乎一样。
>
> **但初始化依然极其重要**——它不影响「最终能到多好」，
> 而是影响「多快能到那里」和「训练会不会直接崩」。

---

## 二、为什么未缩放的初始化是不健康的

### 数学推导

```python
C  = torch.randn((27, 10))          # 字符向量，标准正态
W1 = torch.randn((30, 200))         # 第一层权重，标准正态 ← 问题在这
```

逐层算方差：

| 步骤 | 计算 | 标准差 |
|---|---|---|
| 字符向量 | 每个分量 ~ N(0,1) | 1.0 |
| 拼接 3 个字符（30 维） | `sqrt(30)`（独立变量方差相加） | **5.48** |
| `x @ W1` | 30 项乘积之和，方差 = 30×1×1 = 30 | **5.48** |
| `tanh(±5.48)` | tanh 在 \|x\|>3 时几乎饱和到 ±1 | ≈ **±1** |

### 实测验证

```
未缩放：  线性输出标准差 5.25，tanh 饱和比例 68.7%
×0.2 ：  线性输出标准差 1.05，tanh 饱和比例  4.6%
```

**68.7% 的神经元处于饱和区**——tanh 的输出对它自己的输入几乎不敏感，
反向传播时 `d(tanh)/dx = 1 - tanh² ≈ 0`，梯度被压平。

### 正确做法

让线性输出落在 tanh 的**线性区**（\(|pre| \lesssim 2\)）：

```
W1 的标准差 ≈ 1 / sqrt(fan_in) = 1/sqrt(30) ≈ 0.183
```

Karpathy 用的是 `5/3 / sqrt(fan_in) ≈ 0.304`——那个 `5/3` 是因为
输入 `x` 本身不是严格标准正态，实测方差约为 `1/(5/3)²`。

**这类做法的通用名字叫 "Xavier / Glorot 初始化"**，
PyTorch 里就是 `nn.init.xavier_normal_()`。

## 三、初始 loss 在不同种子下的波动

```
配置                    最小      最大      均值     极差
全部未缩放              23.618   28.599   25.958    4.981
只缩 W1                 17.075   25.964   20.983    8.889
缩 W1+B1                15.714   20.309   17.693    4.594
缩 W1+B1+W2+B2           3.528    3.720    3.620    0.192   ← 稳定
```

**关键观察**：
- 未缩放时初始 loss 稳定在 **24-28**（不是随机到 3）
- 全部缩放后初始 loss 稳定在 **3.5-3.7**，极差只有 0.19

**健康的初始化应该是「模型一开始近似均匀猜测」**，
也就是初始 loss ≈ `ln(vocab_size) = ln(27) = 3.30`。

```
Karpathy 初始化: 3.288  ← 几乎正好等于 ln(27)，完美
用户的缩放:     3.542  ← 很接近
未缩放:        24.0+   ← 远超，说明模型一上来就"自信地猜错"
```

## 四、核心实验：不同训练步数下的对比

**统一在验证集上评估**（这一点很重要，见第六节的踩坑记录）：

| 训练步数 | 原始（未缩放） | 你的手动缩放 | Karpathy 最终版 |
|---|---|---|---|
| **0**（刚初始化） | **24.05** | 3.54 | 3.29 |
| 200 | 9.63 | 2.55 | 2.64 |
| 1,000 | 9.36 | 2.47 | 2.52 |
| 5,000 | 7.41 | 2.38 | 2.41 |
| **100,000** | **2.34** | **2.27** | **2.26** |

早期轨迹（前 2000 步）：

```
初始化              100      300      600     1000     2000
原始（无缩放）      10.52     8.80     8.04     9.36     9.24
你的手动缩放         2.68     2.57     2.59     2.47     2.42
Karpathy 最终版      2.74     2.63     2.68     2.52     2.45
```

### 两个结论

**1. 最终 loss 几乎没差别** → 用户的假设正确

```
100000 步后：2.34 / 2.27 / 2.26   ← 差 0.08，在噪声范围内
```

**2. 但「代价」差了约 1000 倍**

```
「你的缩放」跑      100 步达到 2.68
「未缩放」  跑 100000 步达到 2.34
```

**良好的初始化，把 10 万步的工作压缩到了 100 步。**

## 五、为什么这个模型最终能追平，而深层网络不能

### 这个模型能追平的两个原因

1. **只有 1 个隐藏层**。tanh 饱和虽然让梯度变小，但不存在"逐层衰减"的累积效应——
   浅网络的梯度总能传到第一层。
2. **学习率高达 0.85**。坏初始化可以被足够大的步长跨过去。

### 为什么深层网络里初始化是"生死问题"

层数多了以后，梯度要**连乘**很多次：

| 情况 | 后果 |
|---|---|
| 每层权重略小于临界值 | 梯度逐层**指数衰减** → 浅层收不到梯度 → **梯度消失** |
| 每层权重略大于临界值 | 梯度逐层**指数放大** → 数值爆炸 → **梯度爆炸** |

20 层网络里，每层衰减 0.9，累积就是 `0.9^20 ≈ 0.12`；
每层放大 1.1，累积就是 `1.1^20 ≈ 6.7`。

**这时"多训一会儿"救不回来，训练会彻底停滞。**

> 所以 Karpathy 在第四讲专门讲 BatchNorm——它让每一层的输入分布保持稳定，
> 相当于把「初始化敏感」这个问题从根上缓解掉。

## 六、我自己踩的坑（记录一下）

第一版实验里，初始 loss 是在**训练集前 5000 条**上算的，而最终 loss 在**验证集**上算。

结果「原始」的初始 loss 显示 24.69，看起来"训练让 loss 下降了 22 个点"，
但这个对比**不公平**——两个数字的样本分布不同。

修正为统一在验证集上评估后，数字变成 24.05（差别不大，但口径一致了）。

**教训**：**做对比实验时，所有指标必须在同一批数据、同一口径上计算。**
这也是为什么训练时要分开 `train loss` 和 `val loss`。

## 七、一个我无法完全解释的差异（如实记录）

**用户观察到的初始 loss 约为 3.3，而我的实验里「未缩放」稳定在 24-28。**

我试过：
- 只缩 W1 → 21.0
- 缩 W1+B1 → 17.7
- 全部缩放 → 3.6

都得不到 3.3 这个值。可能的原因：
- 用户的 `mlp_test.py` 在 `random.shuffle` 之后没给 torch 设种子，
  所以 `torch.randn` 用的是每次不同的随机状态——但实测不同种子的波动范围是 23.6-28.6，
  仍然远高于 3.3
- 用户可能是在训练了一段时间之后才打印的
- 或者用户的代码/环境存在我没还原出来的差异

**不影响主结论**，但如实记录在这里。如果以后搞清楚了再补上。
