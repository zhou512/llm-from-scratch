### 1.1 网络：这是最大的坑

实测结果：

```
github.com:443        → 连不上（超时 21 秒）
github.com:22 (SSH)   → 连不上
codeload.github.com   → ✅ 200，1 秒
api.github.com        → ✅ 200，1.6 秒
```

**所以 `git clone https://github.com/...` 现在会失败。** 但 `codeload` 通，意味着可以下 tar 包。
我已经用这个方法把三个候选仓库都拿到本地了（见 `D:\git-reproduce\_candidates\`）。

**推送（push）怎么办？** 等真正要 push 时再解决，几个方向：
- SSH 走 443 端口：`ssh.github.com:443`（GitHub 官方支持，常能绕过 22 端口封锁）
- HTTPS + 代理（你有梯子的话）
- 或者先本地把项目做扎实，最后一次性推上去

> 这个坑对你的复现流程影响不大——**先本地跑通，推送是最后一步**。

### 1.2 8GB 显存意味着什么（重要）

| 能做 | 不能做 |
|---|---|
| ✅ 从零训练小 GPT（character-level Shakespeare） | ❌ 从头训 GPT-2 124M（官方要 8×A100 跑 4 天） |
| ✅ 微调 GPT-2 124M / 355M（用 LoRA 或小 batch） | ❌ 训练 7B 以上模型 |
| ✅ 跑 1B 以下模型做推理（int8/4bit 量化） | ❌ 全参数微调 Llama-3-8B |
| ✅ 复现经典 CV 论文（ResNet、UNet 等） | ❌ 训练 ViT-Large 级别 |

**这个约束不影响我们做「理解型复现」**——我们要的是"搞懂原理并亲手写出来"，不是"训出 SOTA"。

## 2. 三个候选（都已下载到本地）

### 候选 A · micrograd —— 从零实现自动求导引擎

| 维度 | 情况 |
|---|---|
| 仓库 | `karpathy/micrograd` |
| **真实代码量** | **`engine.py` 69 行 + `nn.py` 42 行 = 111 行**（我数过） |
| 依赖 | **零**（纯 Python，不需要 PyTorch） |
| 难度 | ⭐⭐☆☆☆ |
| 工期 | **3–5 天**（每天 2 小时） |
| 硬件 | 任何电脑，CPU 就行 |
| 前置知识 | Python 基础 + 一点点链式法则 |

**你会真正学到**：
- 反向传播**到底是怎么算的**（不是"调用 `loss.backward()` 就完事了"）
- 计算图（DAG）、拓扑排序、链式法则的代码实现
- 为什么 PyTorch 的 `requires_grad` / `.grad` 是那个样子
- 亲手写 SGD 优化器、亲手搭 MLP

**简历上怎么写**：
> 从零实现标量级自动微分引擎（~110 行纯 Python，零依赖），基于动态计算图实现反向传播与拓扑排序，支持 `+ - * / ** relu` 等算子；在其上构建 MLP 库与 SGD 优化器，在 moons 数据集上完成二分类训练。深入理解深度学习框架的自动求导机制。

**为什么排第一**：**投入产出比最高**。5 天、111 行、零依赖，但会让你后面看 nanoGPT 的 `model.py` 时**看得懂**而不是"抄一遍"。这是地基。

**风险**：简历上"111 行"听起来不够唬人 → 靠**博客/笔记**补：写一篇《反向传播是如何工作的：从 micrograd 源码出发》比代码本身更值钱。

### 候选 B · nanoGPT —— 从零训练一个 GPT

| 维度 | 情况 |
|---|---|
| 仓库 | `karpathy/nanoGPT` |
| **真实代码量** | **`model.py` 290 行 + `train.py` 309 行 = 599 行**（核心就这两个文件） |
| 依赖 | torch, numpy, transformers, datasets, tiktoken, wandb, tqdm |
| 难度 | ⭐⭐⭐⭐☆ |
| 工期 | **2–3 周**（每天 2–3 小时） |
| 硬件 | 你的 4070 8GB **够跑 char-level**，需调小 batch |
| 前置知识 | 会 PyTorch 基本操作 + 懂一点 attention 概念 + **建议先做完候选 A** |

**关键事实（我从 README 核实）**：
- 官方：char-level Shakespeare 在 **1 张 A100 上约 3 分钟**，val loss 1.4697
- 你的 4070 慢一些，**预计 15–40 分钟**，完全可接受
- 从头训 GPT-2 124M 官方要 **8×A100 40GB 跑 4 天** → 你**不要碰这个**
- ⚠️ **README 第 9 行说明**：nanoGPT 已于 2025 年 11 月标记为 deprecated，作者推荐看新的 `nanochat`。但 nanoGPT **仍然是最好的教学代码**，且 nanochat 对你的硬件太重，所以选 nanoGPT 是对的。

**你会真正学到**：
- Transformer 的每一块：multi-head attention、LayerNorm、残差、FFN、位置编码
- 语言模型的训练循环：loss 计算、梯度累积、学习率 warmup + cosine decay、梯度裁剪
- tokenizer 是什么（BPE vs character-level）
- 采样/生成：temperature、top-k
- **从 loss 曲线判断模型是否在学**

**简历上怎么写**：
> 复现并逐行解析 nanoGPT（~600 行）的 GPT 训练框架，在单张 RTX 4070（8GB）上从零训练字符级 Transformer 语言模型，结合 Shakespeare 数据集完成训练→采样全流程；针对显存限制调整 batch size 与梯度累积策略，验证 loss 收敛与生成质量；补充中文语料适配与训练日志可视化。

**为什么排第二**：**最贴近当下就业市场**（LLM 是 2025 年最热方向），而且代码只有 600 行——**这是你能"全部读懂"的量级**，不是那种 10 万行的大项目。

**风险**：PyTorch 2.10 + transformers 5.6 太新，可能有 API 不兼容 → 我们会用独立虚拟环境 + 必要时锁版本解决。

### 候选 C · minbpe —— 从零实现 BPE 分词器

| 维度 | 情况 |
|---|---|

| **真实代码量** | `base.py` 150 + `basic.py` 62 + `gpt4.py` 115 + `regex.py` 146 ≈ **477 行** |

**你会真正学到**：

**简历上怎么写**：
> 从零实现 BPE 分词器（含基础版 / 正则版 / GPT-4 版三种实现），复现 GPT-2 的分词规则；对比不同实现对中英文语料的压缩率，分析中文 token 效率问题。

**为什么排第三**：工期短、独立性强，适合当**周末小项目**或主项目之间的调剂。

## 4. 我推荐：不要三选一，按顺序做 A → B，C 当调剂

**理由**：

1. **A 是 B 的前置**。micrograd 让你彻底搞懂反向传播，之后看 nanoGPT 的 `model.py` 才是"读懂"而不是"抄"。
2. **A 只要 5 天**，成本极低，但能立刻建立信心 + 补上最核心的数学直觉。
3. **B 是简历主力**。LLM 方向 + 600 行可全懂 + 有真实训练结果，面试时你能聊 30 分钟。
4. **C 工期短**，可以在 B 卡住时换换脑子，或者作为"我还会这个"的补充。

### 建议的 4 周排期

| 周 | 内容 | 产出 |
|---|---|---|
| 第 1 周 | 候选 A（micrograd）+ 建好项目模板 | 能自己写出反向传播；GitHub 上有一个干净仓库 |
| 第 2 周 | 候选 B 上半：读 `model.py`，逐块拆解 Transformer | 一篇笔记：注意力机制到底在算什么 |
| 第 3 周 | 候选 B 下半：跑训练 + 调参 + 采样 | loss 曲线 + 生成的文本截图 |
| 第 4 周 | 改造 B：换中文语料 / 加可视化 / 写 README | **一个可以放进简历的完整项目仓库** |
