## 一、网络：什么能通，什么不能

实测命令：`curl.exe -sL -m 20 -o NUL -w "%{http_code} %{time_total}s" <url>`

| 目标 | 状态 | 说明 |
|---|---|---|
| `github.com` | ❌ 超时 21s | 主站不通 → `git clone https://github.com/...` 会失败 |
| `github.com:22` (SSH) | ❌ 不通 | `ssh -T git@github.com` 当时能通，但不稳定 |
| `api.github.com` | ✅ 200 / 1.6s | API 可用 |
| `codeload.github.com` | ✅ 200 / 1.1s | **下 tar 包可用** |
| `raw.githubusercontent.com` | ⚠️ 时通时断 | 探测时 200，实际下载 `curl: (56) Connection was reset` |
| `cdn.jsdelivr.net` | ✅ 200 / 8.4s | **GitHub 内容的可靠镜像** |
| `huggingface.co` | ❌ 超时 20s | 不通 |
| `hf-mirror.com` | ✅ 200 / 5.1s | **HF 镜像可用** |
| `gitee.com` | ✅ 200 / 1.0s | 通 |
| `modelscope.cn` | ✅ 200 / 0.4s | 通 |
| `pypi.tuna.tsinghua.edu.cn` | ✅ 200 | 清华 PyPI 镜像可用 |

### 结论与对策

| 想做的事 | 用什么 |
|---|---|
| 下载 GitHub 仓库 | `codeload.github.com/<owner>/<repo>/tar.gz/refs/heads/<branch>` |
| 下载 GitHub 单文件 | `cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/<path>` |
| 下载 HF 模型/数据 | 换 `hf-mirror.com`（设 `HF_ENDPOINT=https://hf-mirror.com`） |
| 装 Python 包 | 清华镜像 `--index-url https://pypi.tuna.tsinghua.edu.cn/simple` |
| push 到 GitHub | 还没验证，候选方案：`ssh.github.com:443` |

> **jsdelivr 踩坑**：路径里有中文要先 percent-encode。
> `urllib` 会报 `UnicodeEncodeError: 'ascii' codec can't encode characters`。
> 解决：`urllib.parse.quote(url, safe=":/?&=@#%[]!$'()*+,;")`

## 二、Python 环境：什么必须装，什么不用装

`nanoGPT` 官方 README 写的是：

```bash
pip install torch numpy transformers datasets tiktoken wandb tqdm
```

**但做 char-level 训练，其中一半是多余的。** 逐个看：

| 包 | 字符级训练需要吗 | 说明 |
|---|---|---|
| torch | ✅ 必须 | 已装 2.10.0+cu126，CUDA 可用 |
| numpy | ✅ 必须 | 已装 2.2.4（读 .bin 用 memmap） |
| transformers | ❌ 不需要 | 只有加载 GPT-2 预训练权重才用 |
| datasets | ❌ 不需要 | 只有下载 OpenWebText 才用 |
| tiktoken | ❌ 不需要 | 只有 BPE 分词才用（字符级用不到） |
| wandb | ❌ 不需要 | 可选日志，`wandb_log=False` 时不会 import |
| tqdm | ⚪ 可选 | 进度条 |

**所以最小依赖就是 torch + numpy。** 这省掉了：
- `datasets` 装不上（要访问 huggingface）
- `transformers 5.6` 太新可能与 nanoGPT 不兼容

> 想练 BPE 分词时再单独装 tiktoken（清华镜像 30 秒装好）。

### 虚拟环境策略

```bash
uv venv .venv --system-site-packages
```

`--system-site-packages` 让虚拟环境**复用系统已装的 torch**，
省掉 2.5GB 重复下载。代价是版本被系统锁定——对学习项目完全够用。

## 三、数据准备：官方脚本的两个坑

### 坑 1：官方 `prepare.py` 直接联网下载

```python
data_url = 'https://raw.githubusercontent.com/karpathy/char-rnn/master/data/tinyshakespeare/input.txt'
with open(input_file_path, 'w') as f:
    f.write(requests.get(data_url).text)
```

在你这台机器上 `raw.githubusercontent.com` **会 reset**。
所以我把数据预先下好放在 `data/input.txt`，并重写了脚本读本地文件。

### 坑 2：`open(path, 'w')` 用系统默认编码

Windows 上默认是 GBK。**写中文语料会直接报错或乱码，而且不一定报错。**

我重写的 `prepare.py` 用 `open(path, 'rb')` + 显式解码（utf-8 → utf-8-sig → gb18030 → gbk），
并在最后加了**往返自检**：

```python
sample = "".join(itos[i] for i in train_ids[:60])
print(f"往返自检: {sample!r}")
```

**这个自检对中文特别重要**——中文编码错了不一定抛异常，可能只是训出一个
只会输出乱码的模型，而你会花几个小时找原因。

### ★ 坑 3：uint16 溢出（中文版的隐藏杀手）

nanoGPT 的 `get_batch` 里写死了：

```python
data = np.memmap(..., dtype=np.uint16, mode='r')
```

`uint16` 最大 **65535**。英文 char-level 词表只有 65，没问题。
但**中文词表动辄几千到几万**，一不小心就溢出。

所以我在 `build_zh_corpus.py` 里加了检查：

```
✅ 词表 9213 < 65536，可以直接用 nanoGPT 默认的 uint16 格式
```

实测中文语料：**1,241,043 字符，词表 9214**，安全。

## 四、中文语料从哪来

`huggingface.co` 不通，大语料（MNBVC 等）几十 GB 也没必要。

**选了 [chinese-poetry](https://github.com/chinese-poetry/chinese-poetry)（via jsdelivr）**：

| 来源 | 篇数 | 字符数 |
|---|---|---|
| 全唐诗（8 个分片） | 7,592 | 677,773 |
| 宋词（4 个分片） | 4,000 | 342,046 |
| 诗经 | 305 | 38,960 |
| 楚辞 | 65 | 34,037 |
| 论语 | 20 | 22,054 |
| 花间集 / 百家姓 / 千字文 | 52 | 5,034 |
| **合计** | **12,034** | **1,142,970** |

优点：公共领域、风格统一、体积刚好（1.1M 字符 ≈ Shakespeare 的量级）、
**词表 9214 在 uint16 范围内**。

缺点：只有古诗文，模型学到的会是文言风格。想学现代中文需要换语料
（可以用 `--input` 指向自己的 txt）。

## 五、实测性能数据（RTX 4070 Laptop 8GB）

### 冒烟测试（`refs/smoke_test.py`）

| 配置 | 参数量 | 峰值显存 | 单步 |
|---|---|---|---|
| tiny（2 层 64 维） | 0.10M | 0.03 GB | 649 ms |
| shakespeare-char（6 层 384 维，词表 65） | 10.7M | 0.37 GB | 81 ms |
| shakespeare-char-zh（6 层 384 维，词表 9214） | 14.2M | 0.65 GB | 49 ms |

（batch_size=8；第一次调用含 CUDA 初始化，所以 tiny 反而慢）

### 真实训练（char-level，batch_size=12 × 梯度累积 4）

```
tokens per iteration will be: 12,288
number of parameters: 10.65M
using fused AdamW: True
step 0:  train loss 4.2853, val loss 4.2743
step 10: train loss 3.0994, val loss 3.1650
step 20: train loss 2.7250, val loss 2.7017
单步耗时: 98-514 ms
```

**20 步 loss 从 4.29 降到 2.72**，说明训练链路完全正常。

按 ~150ms/步估算，官方 5000 步约 **12-15 分钟**（A100 上官方称约 3 分钟）。

> 注意 `mfu`（模型浮点利用率）只有 2-3%。这是单卡笔记本 GPU 的正常水平，
> 因为 batch 小、kernel 启动开销占比高。**面试时可以主动说这点**——
> 说明你知道什么是 MFU 以及它为什么低。
