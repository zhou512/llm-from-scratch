# 笔记 03 · 超参对比实验与结果分析

> 脚本：`experiments/run_experiments.py`
> 原始数据：`outputs/experiments_shakespeare_char.csv`
> 表格：`outputs/experiments_shakespeare_char.md`

---

## 一、实验怎么做的

**控制变量法**：8 组实验，除标注的变量外，其余配置完全一样（都是官方 char-level 配置）。

| 实验 | 改了什么 | 目的 |
|---|---|---|
| baseline | 不改 | 对照组 |
| n_layer=3 / 12 | 层数 | 深度的影响 |
| n_embd=192 / 768 | 嵌入维度 | 宽度的影响 |
| block_size=128 | 上下文长度 | 序列长度的影响 |
| no_dropout / 0.4 | 正则化强度 | 过拟合的影响 |

固定条件：每组训练 **300 步**，batch_size 自动调整（上限 32），seed=1337。

---

## 二、实测结果（RTX 4070 Laptop 8GB）

| 实验 | 参数量(M) | train loss | val loss | ms/iter | 峰值显存(GB) | MFU(%) |
|---|---|---|---|---|---|---|
| baseline | 10.67 | 2.5090 | 2.5082 | 73.8 | 1.40 | 2.53 |
| **n_layer=3** | 5.35 | **2.4586** | **2.4600** | 37.8 | 0.76 | 2.47 |
| n_layer=12 | 21.32 | 2.9672 | 2.9728 | 147.6 | 2.68 | 2.53 |
| **n_embd=192** | 2.68 | **2.4373** | **2.4447** | 27.0 | 0.68 | 1.91 |
| n_embd=768 | 42.58 | 2.5493 | 2.5595 | 254.3 | 3.00 | 2.78 |
| block_size=128 | 10.67 | 2.4661 | 2.4824 | 39.0 | 0.77 | 2.27 |
| no_dropout | 10.67 | 2.5006 | 2.5160 | 77.1 | 1.35 | 2.42 |
| dropout=0.4 | 10.67 | 2.4726 | 2.4769 | 79.7 | 1.40 | 2.34 |

## 三、四个反直觉的发现

### 发现 1：★ 更小的模型反而更好（n_embd=192 打败 baseline）

```
n_embd=192:  2.68M 参数  →  val loss 2.4447  ← 最好
baseline:   10.67M 参数  →  val loss 2.5082
n_embd=768: 42.58M 参数  →  val loss 2.5595  ← 最差
```

**参数越多，loss 越差**，形成倒 U 形。

**原因**：数据集只有 1M 字符、只训 300 步。
大模型参数多、收敛慢，300 步根本喂不饱它；
小模型学得快，反而先到低点。

**这是「容量与数据量不匹配」的经典现象**，也是为什么小数据集上不该盲目加大模型。

### 发现 2：层数翻倍反而变差（n_layer=12）

```
n_layer=3:  5.35M  →  2.4600  ← 好
n_layer=6: 10.67M  →  2.5082  ← baseline
n_layer=12: 21.32M →  2.9728  ← 明显变差
```

12 层的 loss 比 6 层**差了 0.46**，这是很大的差距。

**可能原因**：
1. 同样 300 步，12 层需要更多步才能收敛
2. 深层网络初期更难优化（尽管有 Pre-LN + 缩放初始化）
3. 数据集太小，12 层的容量完全过剩

**验证方法**：把 `--max-iters` 提到 3000 再跑一次，看 12 层会不会反超。
**这个实验你应该自己做一遍**——这正是「知道结论」和「自己验证」的区别。

### 发现 3：上下文减半影响很小（block_size=128）

```
block_size=256: val 2.5082, 73.8ms/iter, 1.40GB
block_size=128: val 2.4824, 39.0ms/iter, 0.77GB
```

**几乎一样的 loss，但显存减半、速度快一倍。**

**原因**：300 步的训练里，模型还没学会利用长距离依赖。
字符级 Shakespeare 的局部模式（单词、短语）用 128 个字符已经足够。

**工程含义**：如果你显存不够，**优先砍 block_size**，代价最小。

### 发现 4：dropout 的影响很小，但方向符合预期

```
no_dropout:  train 2.5006 / val 2.5160   ← 训练集和验证集差距 0.0154
dropout=0.2: train 2.5090 / val 2.5082   ← baseline，差距 -0.0008
dropout=0.4: train 2.4726 / val 2.4769   ← 差距 0.0043
```

训练/验证的差距都很小，说明 **300 步还远没到过拟合的阶段**。
dropout 的作用要等训练充分后才明显。

## 四、★ 一个重要陷阱：loss 不能跨速度直接比较

看这两个：

| 实验 | ms/iter | val loss |
|---|---|---|
| n_embd=192 | 27.0 | 2.4447 |
| baseline | 73.8 | 2.5082 |

n_embd=192 每次迭代快 2.7 倍。**同样 300 步，它用了不到 1/3 的时间。**

公平的比较方式有两种：

| 方式 | 怎么做 |
|---|---|
| **按步数比** | 固定 `max_iters`，比 loss（就是本文的做法） |
| **按时间比** | 固定总时间（如 60 秒），看各模型跑到哪 |

**面试时如果被问"哪个配置更好"，正确回答是**：
> 「在固定 300 步的条件下，n_embd=192 的 val loss 最低（2.44）。
> 但它的单步耗时只有 baseline 的 1/3，所以如果按固定时间预算比较，
> 结论可能不同。我倾向于固定步数比较，因为这样对比的是'模型容量'而非'硬件效率'。」

这个回答体现你知道**实验设计里的混杂变量**，比单纯报数字强得多。

## 五、从显存角度看

| 配置 | 峰值显存 | 你的 8GB 能开多大 batch |
|---|---|---|
| n_embd=192 | 0.68 GB | 可以开很大 |
| baseline | 1.40 GB | 充足 |
| n_layer=12 | 2.68 GB | 够 |
| n_embd=768 | 3.00 GB | 勉强 |

**结论**：8GB 显存对 char-level 训练**绰绰有余**。
真正的瓶颈是「纯 Python 标量运算之外，笔记本 GPU 的算力本身有限」，
以及 MFU 只有 2-3%（batch 太小、序列太短，GPU 吃不满）。

## 六、这个实验的局限（要写进 README 的诚实说明）

1. **只训了 300 步**，而官方配置是 5000 步。大模型在短训练下吃亏，
   所以「小模型更好」的结论**只在这个训练预算下成立**。
2. **只跑了单次**，没有多种子取平均。loss 差异 0.05 以内可能是噪声。
3. **没做学习率搜索**，所有实验都用 1e-3。
4. **只用了英文语料**，中文语料要单独跑一遍（`--dataset zh_char`）。

**把局限写清楚，比假装实验完美更有说服力。** 这也是科研的基本素养。
