## 一、核心心智模型：每个运算都做三件事

引擎的**全部秘密**就在这一个模式里。以乘法为例：

```python
def __mul__(self, other):
    # ① 前向：算出结果值
    out = Value(self.data * other.data, (self, other), '*')

    # ② 登记反向规则：结果拿到梯度后，怎么把梯度分给输入
    def _backward():
        self.grad  += other.data * out.grad
        other.grad += self.data  * out.grad
    out._backward = _backward

    # ③ 返回新节点
    return out
```

| 步骤 | 做什么 | 关键点 |
|---|---|---|
| ① 前向 | 算 `data`，同时把输入记进 `_prev` | `(self, other)` 就是图的边 |
| ② 反向 | 定义「局部导数怎么传回去」 | 用**闭包**捕获 `self/other/out` |
| ③ 返回 | 新节点，带着自己的 `_backward` | 图的构建是**动态**的 |

**局部导数就是链式法则里那一项。** 乘法 `out = a*b`：
- `∂out/∂a = b`
- `∂out/∂b = a`

所以 `a.grad += b.data * out.grad`，`out.grad` 是从下游传上来的。

## 二、`Value` 里每个字段是干什么的

```python
class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data = data                 # 数值本身
        self.grad = 0                    # ∂(最终输出)/∂(本节点)，初始为 0
        self._backward = lambda: None    # 本节点的反向规则，叶子节点是空操作
        self._prev = set(_children)      # 本节点由谁算出来的（图的父节点）
        self._op = _op                   # 产生本节点的运算名，只用于调试/画图
```

- **`_backward` 初始为 `lambda: None`**：因为叶子节点（比如 `Value(2.0)`）没有上游，
  反向传播走到它时什么都不用做。这个设计避免了在 `backward()` 里做 `if` 判断。
- **`_prev` 用 `set`**：同一节点可能被重复引用，用集合天然去重。
- **`_op` 不参与计算**，纯粹是给人看的（`draw_dot` 画图时用）。

## 三、反向传播：为什么必须拓扑排序

```python
def backward(self):
    topo = []
    visited = set()
    def build_topo(v):
        if v not in visited:
            visited.add(v)
            for child in v._prev:
                build_topo(child)
            topo.append(v)      # ★ 后序追加
    build_topo(self)

    self.grad = 1               # 最终输出对自己的导数是 1
    for v in reversed(topo):    # ★ 逆序 = 从输出往输入走
        v._backward()
```

**为什么不能随便遍历？**

看这个菱形依赖：

```
    a
   / \
  b   c
   \ /
    d
```

`d` 的梯度要同时传给 `b` 和 `c`，而 `b`、`c` 的梯度**必须先都算完**，才能正确传给 `a`。
如果先处理 `a`，它拿到的就是残缺的梯度。

**后序 DFS 保证**：一个节点被追加到 `topo` 时，它的所有"孩子"已经在里面了。
所以 `reversed(topo)` 就是「从输出到输入」的正确顺序。

> `self.grad = 1` 这一行的含义：最终输出对自身的导数是 1，
> 这是整条链式法则的种子（seed）。

## 四、三个必须记住的细节

### 细节 1：`+=` 而不是 `=`（最重要）

```python
self.grad += out.grad      # ✅ 累加
self.grad  = out.grad      # ❌ 覆盖
```

**为什么必须累加**：一个节点可能被用到多次。比如 `b = a * a`，
`a` 同时是左操作数和右操作数，梯度要**加起来**才对：

```
db/da = ∂(a*a)/∂a(左边) + ∂(a*a)/∂a(右边) = a + a = 2a
```

测试 `test_gradient_shared_node_accumulates` 和 `test_gradient_diamond` 就是专门抓这个 bug 的。

### 细节 2：运算符重载的镜像方法

| 表达式 | 实际调用 | 容易写错的地方 |
|---|---|---|
| `a + b` | `a.__add__(b)` | — |
| `1 + a` | `a.__radd__(1)` | — |
| `3 - a` | `a.__rsub__(3)` | ⚠️ 顺序！必须是 `other - self` |
| `6 / a` | `a.__rtruediv__(6)` | ⚠️ 顺序！必须是 `other / self` |

`__rsub__` 写反的话，`3 - Value(2)` 会得到 `-1`。测试里专门有 `test_rsub` 抓这个。

### 细节 3：除法不需要单独实现

```python
def __truediv__(self, other):
    return self * other**-1     # 复用乘法和幂运算
```

`a / b` 等价于 `a * b**(-1)`。**只实现加、乘、幂三个基本算子，其余全靠组合。**
这是很好的设计习惯：把逻辑收敛到最少的原语上。

## 五、动手前先手推一个例子

题目：`d = a*b + b**3`，`a = -4, b = 2`，求 `∂d/∂a` 和 `∂d/∂b`。

```
d = a*b + b³
  = (-4)(2) + 8 = -8 + 8 = 0          # 前向值

∂d/∂a = b = 2                          # 只有 a*b 这一项含 a

∂d/∂b = a + 3b²                        # a*b 项给 a；b³ 项给 3b²
      = -4 + 3(4) = -4 + 12 = 8
```

对照测试 `test_gradient_chain`：期望 `a.grad == 2.0`，`b.grad == 8.0`。✅

**做测试之前，先把每个测试的期望值手推一遍。** 手推不出来说明还没读懂，
这时候抄代码是没有意义的。
