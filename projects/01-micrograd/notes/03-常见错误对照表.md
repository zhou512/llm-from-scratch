## A. `test_engine.py` 常见失败

| 失败的测试 | 报错信息 | 原因 | 修法 |
|---|---|---|---|
| `test_value_stores_data` | `AttributeError: 'Value' object has no attribute 'data'` | 忘了在 `__init__` 里存 `self.data` | `self.data = data` |
| `test_value_stores_data` | `assert 0 == 0.0` 之类的类型问题 | `self.grad = 0` 是 int，测试断言 `0.0` | 写 `self.grad = 0.0` |
| `test_value_has_prev_and_op` | `AttributeError: ... has no attribute '_op'` | 属性名写成 `op` 而不是 `_op` | 测试钉的是 `_op`，加下划线 |
| `test_value_has_prev_and_op` | `assert set() == {a, b}` | `__init__` 里没把 `_children` 存进 `_prev` | `self._prev = set(_children)` |
| `test_radd` / `test_rmul` | `TypeError: unsupported operand type(s)` | 没写 `__radd__` / `__rmul__` | 补上，`return self + other` |
| `test_rsub` | `assert -1.0 == 1.0` | `__rsub__` 写成了 `self - other` | 必须是 `other - self`（先取负再加） |
| `test_rtruediv` | `assert 0.5 == 2.0` | `__rtruediv__` 顺序写反 | 必须是 `other / self` |
| `test_relu_negative` | `assert -2.0 == 0.0` | `relu` 忘了截断 | `0 if self.data < 0 else self.data` |
| `test_gradient_chain` | `assert 4.0 == 2.0`（差整数倍） | 局部导数算错 | `a*b` 的 `∂/∂a = b.data`，`∂/∂b = a.data` |
| `test_gradient_shared_node_accumulates` | `assert 3.0 == 6.0` | **用了 `=` 而不是 `+=`** | 所有 `_backward` 里都要 `+=` |
| `test_gradient_diamond` | `assert 12.0 == 15.0` | 同上，梯度没累加 | 同上 |
| `test_gradient_of_karpathy_example` | 数值接近但不完全对 | 某个算子的局部导数错了 | 逐个算子手推验证 |
| 任意测试 | `RecursionError: maximum recursion depth exceeded` | 拓扑排序没记 `visited`，或图里有环 | `build_topo` 里先判断 `if v not in visited` |
| `test_gradient_of_karpathy_example` | `assert 0.0 == 138.8` | `backward()` 里忘了 `self.grad = 1` | 种子梯度必须是 1 |
| `test_gradient_of_karpathy_example` | 梯度全为 0 | `backward()` 里遍历顺序反了 | `for v in reversed(topo)` |
| `test_backward_accumulates_across_calls` | `assert 3.0 == 6.0` | 你以为会重置，其实原实现就是累加 | 这个测试是**文档**，不用改实现 |

### 最容易踩的三个

1. **`=` vs `+=`**（占失败的大头）——一个节点被用两次时，梯度必须相加
2. **`reversed(topo)`**——反向传播必须从输出往输入走
3. **`self.grad = 1`**——种子梯度，忘了它所有梯度都是 0

| `test_mlp_can_reduce_loss_on_toy_data` | `loss 没有下降` | ① 忘了 `zero_grad()` ② 更新写成 `p -= ...` 而不是 `p.data -= ...` | 逐个检查训练循环四步 |

### 训练不收敛的排查顺序

```
1. 有没有调用 model.zero_grad()？
2. 更新参数时改的是 p.data 还是 p？
3. backward() 之前有没有先算 loss（前向）？
4. 学习率是不是太大（loss 震荡/爆炸）或太小（几乎不动）？
5. 最后一层 nonlin 是不是 True（把负值截断了）？
```

## D. 调试方法论（比这张表更重要）

1. **一次只让一个测试变绿**。用 `pytest tests/test_engine.py::test_addition -v` 只跑一个。
2. **打印中间值**。`print(out.data, a.grad, b.grad)` 比盯着报错看有效。
3. **和手推结果对**。每个测试的期望值都可以手算——算不出来说明原理没懂。
4. **二分定位**。如果 `test_gradient_of_karpathy_example` 挂了但其他都过，
   说明是某个**组合运算**的问题，逐个算子单独测。
5. **别急着看 `refs/`**。看一眼就少一次自己想通的机会。真的卡住 20 分钟以上再看。

## F. ★「测试时好时坏」——随机性问题

**症状**：同一个测试，跑 10 次挂 1 次。

**实测案例**：`test_mlp_gradients_reach_first_layer` 曾经约 10% 概率失败：

```
第 8 次: 1 failed in 0.34s      ← 有时挂
第 9 次: 1 passed in 0.02s      ← 有时过
```

**原因**：`MLP` / `Neuron` 用 `random.uniform(-1, 1)` 初始化权重。
ReLU 有个特性叫「**dead ReLU**」——如果某个神经元的加权和恒为负，
它的输出恒为 0，梯度也恒为 0，这个神经元就"死"了。

如果**第一层所有神经元恰好都落在负区间**，那么第一层参数的梯度
自然全是 0，测试的断言 `any(p.grad != 0)` 就会失败。

**这不是实现 bug，是测试没有控制随机性。**

**修法**：用 pytest 的 fixture 在每个测试前固定种子：

```python
import random
import pytest

@pytest.fixture(autouse=True)
def _fixed_random_seed():
    random.seed(1337)
```

`autouse=True` 表示自动应用到文件里每个测试，不用一个个加。

**修完验证**（必须做这一步，不能只跑一次就说修好了）：

```powershell
for ($i=1; $i -le 15; $i++) { .venv\Scripts\python.exe -m pytest tests/ -q }
# 期望：15 次全部通过
```

### 规律总结

| 什么情况 | 处理 |
|---|---|
| 依赖随机初始化的断言 | **必须固定种子** |
| 依赖 `set` / `dict` 遍历顺序 | 排序后再比较（`sorted(...)`） |
| 依赖时间 | 注入假的时钟，别用 `time.time()` |
| 依赖网络/文件系统 | 用 mock，或标记为 `@pytest.mark.slow` 单独跑 |

**核心原则**：**测试必须可复现。** 一个"大部分时候能过"的测试，
比没有测试更糟——它会让你不再相信测试结果。

> 这个坑我在这个项目里踩了 **4 次**（前 3 次是断言写错：属性名、不存在的 API、
> 手推梯度算错）。教训：**测试自己也要被验证**——写完先用参考实现跑一遍，
> 并且**重复跑多次**确认稳定。
