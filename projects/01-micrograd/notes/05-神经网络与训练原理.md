## 一、先把名词和代码对应起来

神经网络听起来玄，其实就是**一堆 `Value` 的加减乘除**。对照你写的代码：

| 名词 | 在你代码里是什么 |
|---|---|
| **神经元 Neuron** | 一个 `Neuron` 对象：`w`（权重列表）+ `b`（偏置） |
| **权重 weight** | `self.w` 里的 `Value`，**要学的参数** |
| **偏置 bias** | `self.b`，也是要学的参数 |
| **层 Layer** | 一组 `Neuron` |
| **网络 MLP** | 几层 `Layer` 串起来 |
| **前向传播 forward** | `model(x)`，从输入算出输出 |
| **损失 loss** | 一个 `Value`，衡量「预测得多差」 |
| **反向传播 backward** | `loss.backward()`，你写的拓扑排序那部分 |
| **梯度 gradient** | 每个参数的 `.grad` |
| **训练 training** | 反复「前向 → 算损失 → 反向 → 更新参数」 |

**最重要的一句话**：
> 神经网络里**没有任何魔法**，所有运算最终都是你 `engine.py` 里的
> `+`、`*`、`**`、`relu`。你的 `Value` 类就是 PyTorch 的核心。

## 二、一个神经元在算什么

```python
def __call__(self, x):
    act = sum((wi * xi for wi, xi in zip(self.w, x)), self.b)
    return act.relu() if self.nonlin else act
```

拆开就是：

```
act = b + w0*x0 + w1*x1 + ... + wn*xn      # ① 加权求和
out = relu(act)                             # ② 过一个非线性函数
```

**几何意义**：`w0*x0 + w1*x1 + b = 0` 是二维平面上的一条**直线**。
`relu` 把它变成「直线一侧为 0，另一侧线性增长」的样子。

所以一个神经元 = **画一条线，然后决定线两侧怎么响应**。

## 三、前向传播：算出预测值

```python
model = MLP(2, [8, 8, 1])
pred = model([Value(1.0), Value(2.0)])     # 一个数字
```

数据流过：

```
输入 x (2 个数)
   ↓ Layer(2 → 8)：8 个神经元，每个算一次加权和 + relu
8 个数
   ↓ Layer(8 → 8)
8 个数
   ↓ Layer(8 → 1)：1 个神经元，不加 relu
pred (1 个数)
```

**这一步只是计算，不涉及学习。** 参数还是随机的，所以 `pred` 也是随机的。

## 四、损失函数：把「多差」变成一个数字

我们用的是 SVM（hinge）损失：

```python
loss_i = (1 - y_i * pred_i).relu()          # 单个样本的损失
loss = mean(loss_i)                          # 整个数据集的平均
```

其中 `y` 是标签 `+1` 或 `-1`。

### 为什么这个公式能衡量好坏

看 `y * pred` 这个乘积：

| 情况 | `y*pred` | `1 - y*pred` | relu 后 | 含义 |
|---|---|---|---|---|
| 分对，且很有把握（pred 很大且符号对） | ≥ 1 | ≤ 0 | **0** | 完全没损失 ✅ |
| 分对，但不够自信 | 0 ~ 1 | 0 ~ 1 | 0 ~ 1 | 有一点损失 |
| 分错 | < 0 | > 1 | > 1 | 损失大于 1 ❌ |

**所以「损失」的含义是：把所有样本的"不满意程度"加起来平均。**
训练的目标就是**让它变到最小**。

### 为什么 relu 在这里出现

`(...).relu()` 表示「分对了就不惩罚」。没有它的话，模型会无休止地
把 `y*pred` 推到无穷大（为了让 `1-y*pred` 变成负数，越负"损失"越小），
那不是我们想要的。

## 五、梯度：损失对每个参数的「敏感度」

这是你已经实现的部分。回顾：

```python
loss.backward()          # 你写的拓扑排序 + 逆序调用 _backward
```

跑完之后，每个参数的 `.grad` 就是：

```
∂loss / ∂w      「w 稍微变大一点，loss 会怎么变」
```

**几何直觉**：把 loss 想象成一座山，参数是地面上的坐标。
梯度就是**当前位置最陡的下坡方向**。

- `grad > 0`：w 变大，loss 变大 → 应该**减小** w
- `grad < 0`：w 变大，loss 变小 → 应该**增大** w

---

## 六、梯度下降：按梯度反方向走一小步

```python
for p in model.parameters():
    p.data -= lr * p.grad
```

| 符号 | 含义 |
|---|---|
| `p.data` | 参数的值（**注意不是 `p`**，见下面的坑） |
| `lr` | 学习率 learning rate，步长 |
| `p.grad` | 梯度 |

**为什么要减**：梯度指向"loss 上升最快"的方向，所以要往**反方向**走。

**为什么 `lr` 不能太大**：步子太大会跨过谷底，甚至震荡发散。

**★ 新手最容易踩的坑**：

```python
p.data -= lr * p.grad      # ✅ 改「值」
p -= lr * p.grad           # ❌ 把 p 变成一个全新的 Value！
```

第二种写法会把 `p` 重新绑定到一个新对象上，而这个新对象**不在
`model.parameters()` 里**——你的参数根本没被更新，训练静默失效。
（`nn.py` 里 `zero_grad` 写成 `v.grad = 0.0` 也是同理：改的是属性。）

---

## 七、为什么必须 `zero_grad()`

回忆你写测试时发现的行为：**`backward()` 是累加梯度的**。

所以如果不清零：

```
第 1 步：w.grad = 0.5      → w 更新
第 2 步：w.grad = 0.5+0.4 = 0.9   ← 混进了上一步的梯度！
第 3 步：w.grad = 0.9+0.3 = 1.2   ← 越滚越大
```

**梯度会累积成"历史平均值"，训练方向就错了。**

所以训练循环里**每步必须先清零**：

```python
for step in range(steps):
    loss = compute_loss()     # ① 前向 + 算损失
    model.zero_grad()         # ② 清梯度 ← 别忘了
    loss.backward()           # ③ 反向传播
    for p in model.parameters():
        p.data -= lr * p.grad # ④ 更新参数
```

**PyTorch 里 `optimizer.zero_grad()` 干的是同一件事。**

---

## 八、为什么叫"训练"：重复很多次

我们的 `train.py` 里是：

```python
for step in range(steps):     # steps = 100（默认）
    ... 前向 / 反向 / 更新 ...
```

**一次更新只走一小步**，要走几百上千次才能到谷底。

在你的实验中：

```
step    0  loss 0.9398  acc 0.690     ← 随机初始化，基本在瞎猜
step   20  loss 0.6580  acc 0.720
step   40  loss 0.3621  acc 0.820
step   60  loss 0.3029  acc 0.860
step   99  loss 0.2469  acc 0.860     ← 学出来了
```

**loss 下降 = 参数在往正确方向走 = 模型在"学"。**

## 九、把你在 `notes/02` 里答不出的问题补上

### Q2：最后一层加 ReLU，训练效果怎么变？

实测（`tools/experiment_last_layer.py`）：

| | loss | 准确率 | 负类样本的输出范围 |
|---|---|---|---|
| 不加 ReLU（正确） | 0.937 → **0.244** | 86% | [-1.48, +1.18] |
| 加 ReLU | 0.992 → **0.618** | 85% | [**0.00**, +1.08] |

**原因**：SVM 损失需要模型输出**负数**来表达"这是负类"。
ReLU 把所有负值砍成 0，输出只能落在 `[0, +∞)`。

于是对负类样本（`y = -1`）：

```
-y * pred = +pred >= 0
1 + pred >= 1
→ 损失永远 >= 1，永远降不下来
```

**结论**：**输出层不加 ReLU**。多分类也同理（通常用 softmax 或线性输出）。

### Q3：`Layer` 改成永远返回列表，要改哪里？

`train.py` 里所有 `model(x)` 的地方：

```python
# svm_loss 里
preds = [model(x) for x in xs]        →  [model(x)[0] for x in xs]

# accuracy 里
pred = model(x).data                   →  model(x)[0].data
```

还要改 `MLP.__call__` 的最外层返回、以及任何假设"输出是标量"的辅助函数。

**原作者为什么留这个特例**：省掉每次写 `[0]`。代价是返回类型不统一
（1 个神经元返回标量，多个返回列表）——典型的 API 设计取舍。

### Q4：决策边界为什么不是直线？

**如果没有非线性激活函数**，多层线性变换复合起来**还是一次线性变换**：

```
y = W2(W1·x + b1) + b2 = (W2·W1)·x + (W2·b1 + b2) = W·x + b
```

所以边界必然是一条直线。

**ReLU 带来非线性**，把空间"折弯"了。每个神经元的折线拐点在
`w·x + b = 0` 上；多个神经元就有多条折线，组合成**分段线性的曲面**，
所以边界是**由许多小直线段拼成的曲线**，能绕着半月形弯曲。

**你可以自己验证**（跑三次，对比生成的 `decision_boundary.png`）：

```powershell
.venv\Scripts\python.exe src\train.py --hidden 2  --steps 200
.venv\Scripts\python.exe src\train.py --hidden 8  --steps 200
.venv\Scripts\python.exe src\train.py --hidden 32 --steps 200
```

预期：`hidden 2` 边界很粗糙（几段直线）、准确率低；`hidden 32` 更贴合数据。
